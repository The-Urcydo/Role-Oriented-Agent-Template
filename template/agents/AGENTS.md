# agents/ rules

- `agents/` is the tool-neutral source of truth for how agents work. Adapter outputs (`.claude/`, `.cursor/rules/`, `CLAUDE.md` shims, `.github/copilot-instructions.md`, `.gemini/settings.json`) and `ROSTER.md` are generated from it: edit here, then run `python3 tools/sync_indexes.py && python3 tools/sync_agents.py`.
- Changes anywhere under `agents/` change every agent's behavior. They need the human's approval before merging.
- A role is a folder `agents/roles/<role>/` holding its charter `ROLE.md`; `role:` equals the folder name. Required front matter: `role`, `mission`, `reads`, `skills`, `never`, `done_when`, `escalate_when`. Optional: `item_files`, `writes_files`, `access`, `use_when` (`docs/dev/reference/front-matter.md`). `skills:` names the skills the role uses; each must exist in `agents/skills/`. Folder ownership is declared in each folder's `README.md` (`owner_role`), not in the charter.
- A skill is a folder `agents/skills/<name>/SKILL.md` in the open Agent Skills format, and all skills sit in that one folder (`.claude/skills/` is flat too). `name` equals the folder, `description` says what it does and when to use it. Keep the body to about 40 lines; put detail in `references/`. The front matter holds only specification fields: `metadata.requires: work-tracker` marks a skill that needs this repo's tracker, `metadata.invocation: user` one that only the owner starts. Tool-specific fields are generated into each tool's copy. To add or change one, use `write-skill`.
- Charter and method: `ROLE.md` holds the routing (every command that changes who owns an item or its status, with its condition) and the limits. A skill holds the method (read order, checks, templates, commands that do not move the item). A fact lives in one of them, never both. A skill that needs this repo's tracker is written concretely; any other skill stays neutral, with no repo commands. The Claude adapter preloads the skills that only one role lists.
- Protocols are the rules between roles. A protocol never repeats a skill's steps, and a skill never repeats a protocol's rules: link to the one that holds the fact.
- Keep every instruction concrete and testable. Delete anything an agent could discover by reading the repo.
- Never put secrets or personal paths in anything under `agents/`.
